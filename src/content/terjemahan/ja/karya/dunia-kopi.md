## これは何か

一つのコーヒー売り手（アラビカ、ロブスタ、ブレンド）のためのオンラインショップです。カタログ、カート、購入手続き、支払い、注文状況の追跡という、マーケットプレイスでおなじみの流れをそのまま使えます。違うのは、店が一つだけで、買い手が登録しなくていいことです。

買い手は欲しいグラム数を自分で入力し、豆か粉かを選び、粉なら挽き方（トゥブルック、V60、エスプレッソ、フレンチプレス）を選びます。価格と送料は 100 g ごと、ゾーンごとの 1 kg 単価でサーバーが計算します。ブラウザから来た価格は決して信用しません。

## 方針

- **買い手のデータは最小限：** 名前、電話番号、配送先住所だけ。古い注文データは自動で匿名化します。
- **アカウント不要の購入手続き。** 注文は注文コードと電話番号で追跡します。
- **決済代行なしでも支払える。** 固定 QRIS と手動確認を、Midtrans の予備として常に用意しています。
- **外部の解析ツールもトラッカーもなし。**
- **スマホで快適に。** 買い手の多くはスマホを使うと想定しています。

## 作ったもの

M0 から M7 までのマイルストーンはすべて完了し、それぞれ個別のプルリクエストで取り込みました。

| マイルストーン | 内容 |
| --- | --- |
| M1 | 公開カタログと価格計算 |
| M2 | 管理画面：試行回数制限付きのログイン、管理者とスタッフの役割、商品、写真、在庫 |
| M3 | カートと購入手続き。同時に注文されても在庫はマイナスにならず、注文が期限切れになれば一度だけ正確に戻ります |
| M4 | 決済：手動 QRIS と Midtrans。署名を検証し、重複しても一度しか効かない Webhook |
| M5 | 注文管理、状態の履歴、追跡番号、印刷できる準備リスト |
| M6 | 堅牢化：購入の流れ全体のテスト、役割ごとの認可マトリクス、CSRF、厳しい CSP |
| M7 | 依頼主の回答に沿った修正：重さは自由入力、商品ごとの挽き方、配送注文のみ |

その後 SvelteKit 3 に移行し、見た目を6段階で作り直しました。監査、デザインシステム、ホームと絞り込みのできるカタログ、商品詳細ページ、3ステップのカートと購入手続き、そしてレスポンシブな WebP 写真と SEO です。

## ありのままの状況

コードは完成していますが、サイトはまだ公開されていません。残っているのはコードの外のこと、つまりホスティングの選択、決済用のアカウント、まだ下書きのプライバシーポリシーと利用規約、店舗データ、送料です。Midtrans の決済は模擬サーバーでしか試しておらず、本物のサンドボックスでのテストはキー待ちです。Lighthouse のスコアも、実際の商品写真が入ったら測り直す必要があります。
