## これは何か

Project HOME（*High Operative Management Environment*）は、中古のセットトップボックスで動く個人用ホームラボです。機種は Fiberhome HG680P で、Amlogic S905X、Cortex-A53 が4コア、RAM は約1.9 GB、OS は Armbian。システムは 7.3 GB の eMMC に、データは 128 GB の microSD に置いています。

リポジトリが**唯一の正解**です。ボックスに入っているものはすべて、基盤スクリプト、設定、各サービスの compose ファイル、復旧ガイドを含め、リポジトリから作り直せなければなりません。すべてのサービスはローカルネットワーク専用で、インターネットには何も公開していません。

Stardance（Hack Club）のプロジェクトとして登録しています。

## すべてを形づくる制約

このボックスには HDMI がありません。起動か SSH が壊れたら、戻る方法はゼロから書き込み直すことだけです。そこからルールが決まります。

- **カーネル、DTB、ブートローダー、`/boot` には決して触れない。** `/boot` に書き込むパッケージは保留し、initramfs は凍結し、自動更新は切ってあります。227パッケージの更新が安全だったことは、`/boot` の168ファイルの md5 を前後で比べて証明しました。すべて一致です。
- **SSH やネットワークの変更には必ず自動ロールバックのタイマーを使う。** 設定を間違えても、自動で元に戻ります。
- **再起動は許可を得てから**、そしてマウント表を確認してからだけ。

## すでに動いているもの

フェーズ0（基盤）とフェーズ1（4つのサービス）が完了し、2026年9月28日に再起動テストに合格しました。

| サービス | 役割 |
| --- | --- |
| Homepage | ダッシュボード：全サービスへのリンクと、ボックスの CPU・RAM・温度 |
| Uptime Kuma | サービスとバックアップの死活監視 |
| Gitea | 個人用 Git サーバー。GitHub のリポジトリをミラー |
| FileBrowser Quantum | データフォルダ用のウェブファイルマネージャー |

各イメージは arm64 対応のバージョンに固定し、メモリ上限を設けています。すべてのサービスは再起動後に自動で立ち上がり、Docker はデータ用カードがマウントされてから起動します。元の FileBrowser は、セキュリティパッチのないままアーカイブされたので、あえて使っていません。

セキュリティ：SSH は鍵認証のみ、Docker ソケットにアクセスできるコンテナはなし、使わない標準サービスは停止、リポジトリにパスワードはひとつもありません。

## 証明済みのバックアップ

ノートパソコンへの毎日の暗号化バックアップ（restic）は9月29日から動いています。毎週の整合性チェックと、26時間成功したバックアップがなければ赤くなる監視つきです。バックアップは**復元テストに合格して**はじめて存在するとみなし、復元の手順はガイドとしてリポジトリに書いてあります。

順調ではなかったことも記録に残っています。ノートパソコン側の準備スクリプトは正しく動くまでに2回失敗し、最初のバックアップツールの組み合わせは Windows の SFTP サーバーと合わなかったので、経路を変えました。

## 記録に残した失敗ひとつ

ボックス内蔵の SD スロットから microSD をフォーマットしようとしたとき、消去コマンドが I/O エラーで失敗しました。作業を止めて報告し、ノートパソコンで別にテストするまでカードには触れませんでした。118,875 MB を書き込んで検証し、エラーはゼロ。カードは健全で、問題はボックスの SD スロットでした。同じカードを USB カードリーダー経由でつなぎ直し、内蔵 SD スロットは書面のルールで使用禁止にしました。

すべての変更は、日付、内容、理由とともにログに記録しています。失敗したものも含めてです。

## Landship から

Landship は、もともと独立したプロジェクトとして計画していました。すべての作品のための「基地」で、作業を記録し開発日誌を自動でまとめる VTLS（Vault Tracking & Log System）というシステムを持つものです。この計画はもう単独ではなく、アイデアは Project HOME と Project Nor-4 に統合されました。
